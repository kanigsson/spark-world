# ore

Proved SPARK building blocks for bounded, heap-free systems code: the root
package `Ore` with the physical types (`Byte`, `Word16/32/64`, `Byte_Array`,
`Byte_Order`, the capacity ceiling), and three self-contained children —
`Ore.Byte_Buffers`, `Ore.Bits`, `Ore.Bit_Cursors`.

## Scope is set by clients

This was once meant to become a general SPARK standard library; it is not that
any more, and its roadmap was deleted rather than left to be re-adopted. What
is here is what a real client needed: all three child packages exist because
the DEFLATE codec in `inflate` needed them.

So: **do not add a package here because it would round out the library.** Code
that one program needs is grown inside that program and promoted when a second
one wants it — the repository-wide promotion rule, of which this library is the
destination. `FEEDBACK.md` is the record of that demand, written from the
client's side: what Ore replaced, what it did not, and where a gap made the
client keep code this library was supposed to remove. Read it before adding
anything; add to it when a client hits a gap.

`TODO.md` is for work on what is already here — proof cost, contract shape.
Entries in `CHANGELOG.md` and `FEEDBACK.md` from before 0.5.0 refer to a
`ROADMAP.md` that no longer exists; they are history and were left as written.

## Contract conventions

Two hold throughout, and a change that breaks either is a change of direction,
not a detail:

- Contracts state facts **element by element** — bit by bit for a word —
  rather than as slice equalities or over a functional-sequence model. That is
  the form a client's own checks need; the cost is that transitivity and
  carrying a fact across a later write have to be supplied explicitly, which is
  what the lemmas in each package are for.
- Each package ships predicates and lemmas meant for client proofs, not only
  its own. The proof clients under `tests/proof` exist to check that they are
  usable from outside; a new lemma needs one.

## Build, test, prove

```sh
gprbuild  -P ore_lib.gpr                          # debug: contracts on
gprbuild  -P ore_lib.gpr -XORE_BUILD_MODE=release # -O2, contracts dropped
gnatprove -P ore_lib.gpr                          # the library alone: 2069 checks
gnatprove -P ore.gpr                              # library + proof clients: 2278
gprbuild  -P tests/runtime/runtime_tests.gpr && obj/runtime_tests/bit_tests
python3   tools/proof_status.py                   # regenerates PROOF_STATUS.md
```

Two proof projects, and the difference matters. `ore_lib.gpr` proves `src/`
only, which is what `PROOF_STATUS.md` reports and what a client inherits.
`ore.gpr` adds the proof clients under `tests/proof`, whose whole purpose is to
fail when a predicate or lemma is unusable from outside the library — a change
to a contract can leave the library proving clean and break them. Prove through
`ore.gpr` before calling a contract change done. Both carry the same switches:
`--mode=all --level=2 --timeout=180`.

A third build mode, `restrictions`, is a debug build that additionally checks
the library against its restricted-runtime promise (`restrictions.adc`). It
writes to its own `obj/`/`lib-restrictions` directories so that checking the
promise never replaces artifacts that were built, proved and installed.

The 180-second timeout is the margin the slowest goal needs — a bit-level
contract on a 64-bit word under a variable shift — when a whole-library run
competes for the cores, not a typical proof time. `TODO.md` carries the plan to
bring it down.

`PROOF_STATUS.md` is generated by `tools/proof_status.py`; do not hand-edit it.
Platinum levels are declared in `proof_levels.json`, since no tool can decide
that a specification is complete.

## SPARK posture

Proves clean: gold on all three child packages, 100% of checks. The 16 entities
outside SPARK in `Ore.Bits` are the shift and rotate intrinsics, which have no
body to analyse and are modelled natively by GNATprove. Keep it that way — an
unproved check here is a check every client inherits.

## Clients

`inflate` withs `../../libs/ore/ore_lib.gpr`. It is the only client today, and
the reason to keep `FEEDBACK.md` honest.
